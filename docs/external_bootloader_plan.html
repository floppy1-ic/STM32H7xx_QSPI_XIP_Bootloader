External QSPI Bootloader — Design Plan

STM32H750VBTx · Bootloader in internal flash · Application in W25Q64 (XIP)
Copyright © 2026 Sibun

Simple explanation

The bootloader always lives in the MCU’s 128 KB internal flash, starting at 0x08000000. After reset, only this code runs first.

The application lives on the external W25Q64 chip. When programming, the driver uses flash offset 0x00000000. When executing, the CPU sees it at XIP address 0x90000000 (after memory-mapped mode is enabled).

On every boot, the bootloader reads a write_bin flag:

  • Flag ON — Program a new application binary into external flash (indirect QSPI mode), clear the flag, turn memory-mapped mode back on, then soft reset so the bootloader runs again cleanly.
  • Flag OFF — Enable memory-mapped mode, check that a valid vector table exists at 0x90000000, then jump into the application.

After a successful flash, you use a soft reset (not a direct jump) so peripherals and NVIC state are left in a known state; on the next boot the flag is already OFF and the normal jump path runs.

Your six rules (numbered plan)

  1. Bootloader default address — Link and run from internal flash 0x08000000 (128 KB). CubeIDE linker: STM32H750VBTX_FLASH.ld.
  2. Always check write_bin flag first — Before jump or flash logic, read persistent flag (RTC backup, backup SRAM, or dedicated flash sector — TBD in implementation).
  3. If flag enabled — Call QSPI_Flash_DisableMemoryMappedMode() so the QSPI peripheral can use indirect program/erase commands.
  4. If memory-mapped mode is off — Write application .bin to external flash starting at offset 0x00000000 via QSPI_Flash_Erase* + QSPI_Flash_Write.
  5. Normal boot (flag OFF) — Enable memory-mapped mode, validate vector table at 0x90000000, qspi_app_jump_to_application().
  6. After flash complete (flag was ON) — Clear write_bin, enable memory-mapped mode, then soft reset (NVIC_SystemReset()). Bootloader runs again; flag is OFF → step 5 path → jump to app.
Note on step 5 vs 6: After programming, use soft reset (step 6), not an immediate jump. The second boot performs validation and jump with a clean core state.
